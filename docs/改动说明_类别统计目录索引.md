# 改动说明：类别统计改用目录索引（D 项）

**日期** 2026-11-06 · **文件** `ui/class_table.py`（唯一改动的代码文件）· **改动量** +50 / −12

---

## 一、为什么要改

打开/切换工程时主线程卡顿，抓栈定位到 `_compute_counts()` → `_count_segmentation()` →
`_seg_class_ids()` 里的 `p.stat()`。

`_seg_class_ids` 要判断「这张图属于哪些类」，优先读 labelme JSON；读不到就走兜底，
去 stat 掩膜 PNG 和 det.json。眉山中航这个工程 2001 个 JSON 里有 1792 个是空的，
所以绝大多数图都落到兜底路径，每张图 stat 两个文件。

实测：4002 次 stat 共 134ms，而一次 `os.scandir` 扫完整个目录只要 4.8ms。

## 二、改了什么

三处，都在 `ClassTableView` 里。

**1. 新增 `_dir_index(d)`（静态方法）**

```python
with os.scandir(str(d)) as it:
    for e in it:
        if not e.is_file():
            continue
        st = e.stat()
        idx[e.name] = (st.st_mtime_ns, st.st_size)
```

一次遍历拿到 `{文件名: (mtime_ns, size)}`。Windows 上 `FindFirstFile` 一次就把条目属性带回来，
所以这比 N 次 `os.stat` 便宜得多。

**2. `_count_segmentation` 开头建立两个快照**

```python
self._img_index = self._dir_index(img_dir)
self._ann_index = self._dir_index(ann_dir)
groups = {}
for name in self._img_index:          # 原来是 for f in sorted(img_dir.iterdir())
    stem, ext = os.path.splitext(name)
    if ext.lower() not in _IMG_EXT:
        continue
    groups.setdefault(_group_key(stem), []).append(img_dir / name)
for key in sorted(groups):            # 原来是 for key, files in groups.items()
    files = groups[key]
```

**3. `_seg_class_ids` 的签名计算改用快照**

```python
for p, index in ((mpath, idx_ann), (dpath, idx_img)):
    if index:
        info = index.get(p.name)       # 名字不在里面就是文件不存在，不必再 stat
    else:
        info = ... p.stat() ...        # 没有快照就退回旧逻辑
    sig.append(info)
```

`sig` 的语义没变，仍然是 `(mtime_ns, size)`，所以 `_fb_cache` 的失效判断完全等价。

## 三、怎么验的

不是为了「看着像对」，是把改动前后的结果 dump 成 JSON 逐字比对。

探针把 `_compute_counts()` 的返回值和 `_split_bases` 全部序列化，用 `git stash` 切到改动前再跑一次，
然后 diff 两份 JSON。

**两个工程，都完全一致：**

| 工程 | 规模 | counts | split_bases | 耗时（前 → 后） |
|---|---|---|---|---|
| 眉山中航 | 2001 张 / 209 掩膜 | 一致 | 一致 | 1500 → 1224 ms（−18%） |
| 新松 233（多视图 te_0/1/2） | 198 张 / 33 掩膜 | 一致 | 一致 | 631 → 600 ms（−5%） |

多视图那个是重点：分组逻辑依赖文件名（`_group_key(stem)`、`te_0` 优先排序），
从 `f.stem` 换成 `os.path.splitext(name)[0]` 之后，各类计数和 `split_bases` 都没变，
说明分组没被改坏。

> 注：一开始测出多视图工程「变慢 3 倍」，交换前后顺序重测后恢复正常（595/599 vs 606/631）。
> 那次 1849ms 是磁盘和系统负载波动，不是改动引入的。

回归：8 个测试脚本全绿（smoke / close_event / load_progress / mask_stats_cache /
mask_stats / task_queue / imgio_dtype / grouped_sampler）。

## 四、请重点核对这几处

1. **`e.is_file()` 与原 `f.is_file()` 等价吗** —— `DirEntry.is_file()` 会跟随符号链接，
   `Path.is_file()` 也是；子目录两边都跳过。
2. **`groups` 的遍历顺序变了**（原来按路径排序，现在按 key 排序）—— 计数是累加、`split_bases` 是 set，
   理论上与顺序无关，但要确认没有别的地方依赖插入顺序。
3. **`if index:` 这个分支** —— 空字典走 `else` 退回 stat。什么时候会是空？
   `annotations` 目录不存在、或 scandir 抛 OSError。工程没标注时就是这样，要确认那条路径仍然正确。
4. **快照与文件变更的时间差** —— `_img_index` 在 `_count_segmentation` 开头建，
   同一帧内不会变；但如果统计过程中有别的线程写标注，快照就是旧的。
   当前这个函数只在主线程跑，暂无并发。

## 五、遗留

- `_img_index` / `_ann_index` 挂在 `self` 上，`_count_segmentation` 每次覆盖。
  如果以后把这个函数挪到后台线程（C 项），这两个属性会变成跨线程共享，届时要么改成局部变量传入，
  要么加锁。**这是 C 项必须一起处理的地方。**
- 这一项只省 276ms，单看收益不大。它的作用是把「目录快照」这个能力建起来——
  B 项（结果缓存）的失效判断要用同一个快照，届时可以复用 `_dir_index`。

## 六、审核意见处理（2026-11-06 第二轮）

审核方自己造了同规模目录复刻逻辑，逐项比对后判「通过」，同时提了 4 条建议。
全部核实成立，已改：

**1. `if index:` 改成 `if index is not None:`（改动实质）**

原写法下 `annotations/` 不存在时 `_ann_index == {}`，`if index:` 判 False，于是退回逐张 stat。
而「未标注的新工程」正好是这个状态 —— 收益在用户最常见的场景里打了折扣。

现在 `_dir_index` 区分两种失败：

```python
except FileNotFoundError:
    return {}        # 目录不存在 == 里面没有文件，空快照就对了
except OSError:
    return None      # 读失败：不能当成「文件都不存在」
```

调用方只在 `index is None` 时退回 stat。空快照按「查不到 = 文件不存在」处理，
与旧逻辑结果一致，但不再花 stat 的钱。

实测（2001 张图、无 annotations 的临时工程）：**179 ms → 153 ms**。

**2. 顺手省掉 `Path.name`**

`sig` 计算原来对每个 path 调 `p.name`（内部 `os.path.split`）。改成在拼路径时就把
文件名字符串留下，查表直接用字符串：

```python
mname = stem + "_mask.png"
for p, name, index in ((mpath, mname, idx_ann), (dpath, dname, idx_img)):
    info = index.get(name) if index is not None else ...
```

**3. `set_project_dir` 里重置快照**

`changed` 分支加了 `self._img_index = self._ann_index = None`。
当前靠「每次重建 + 只有一个调用点」保证不串工程，但 C 项（挪后台线程）时这两个属性
会变成跨线程共享，提前清掉省一个坑。

**4. 注释修正**

`_dir_index` 的 docstring 明确写了「收录的是目录下所有文件，不只是图片」，
并点明 `images/` 里还放着 `_det.json`，防止以后有人把它当图片索引用。

### 审核指出的归因问题（我原来写漏了）

原文档把收益全归给「4002 次 stat」，不准确。审核方分阶段测出来：

| 阶段 | 旧 | 新 |
|---|---|---|
| 图片枚举（`sorted(iterdir)` + `is_file`） | 194.5 ms | 2.5 ms |
| `sig` 计算（逐张 stat → 查表） | 168.4 ms | 8.8 ms |

枚举那 192ms 比 stat 的 160ms 还大。这点对 B 项有影响：**B 的失效判断不能只想着优化 stat，
枚举这块也要走快照**，否则 192ms 会漏掉。
