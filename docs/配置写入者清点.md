## 二、风险排序（写完这张表才看得出来）

### P0 —— 「平台起不来」：`.ai_training_config.json`（已修）

```python
def load_config():                                    # 改前
    if os.path.exists(CONFIG_FILE):
        with open(CONFIG_FILE) as f:
            return json.load(f)                       # ← 半截 JSON 直接抛
    return {"workspace": ..., "recent_projects": []}
```

调用点 `main_window.__init__:176` 是 `self.config = load_config()`，**外面没有 try**。
而 `save_config` 又是 `open(w)` 非原子 —— **保存时崩一次，下次启动就永远抛**。

实测（`tests/test_config_files.py` 里那条端到端用例）：

```
★ 建窗口失败: JSONDecodeError : Expecting property name enclosed in double quotes: line 1 column 23
```

用户看到的现象：**双击图标，什么都没发生**。没有界面告诉他配置坏了。

> 诚实补一句：这台机器上 `~/.ai_training_config.json` **不存在**（只有改过工作区
> 才会创建），所以现在还没触发。但凡是改过工作区的人，文件就在，链条就成立。
> 这类"启动即死"的 bug 不值得赌概率。

**改法（两头都堵）**：写 → 临时文件 + `os.replace`；读 → 解析失败把坏文件改名
成 `*.bad` 留档、返回默认值，并与 `DEFAULT_CONFIG` **合并**（老文件缺 `workspace`
也不会 KeyError）。

### P3 —— 纯记录，需要产品决定

1. **`main_window._save_ui_setting()` 根本不落盘。**
   ```python
   def _save_ui_setting(self, key, value):
       self._ui_settings[key] = value        # 只进内存
   ```
   而 `_load_ui_setting()` 也只读这个内存字典 —— 没有任何地方把 `.ui_settings.json`
   读进 `_ui_settings`。所以"UI 设置"**重启就丢**（主题是例外，`ui/themes.py`
   自己直接写文件）。这不是写坏，是**从来没写过**。
2. **`project_manager.save_project_meta()` 没有任何调用方**，而它的语义是
   "整份覆盖 `project.json`" —— 谁第一个调用它，谁就把 `classes` / `task_type`
   之外的东西全抹掉。要么删掉，要么改成合并。
3. **`main_window._save_classes_to_project()` 在文件不存在时静默什么都不做**：
   ```python
   if os.path.exists(config_path):
       ...  # 只有文件存在才写
   ```
   工程目录没有 `project.json` 时，改类别名**一点效果都没有**，也不报错。
4. **对话框的 `tile`/`tile_size`/`tile_stride`/`tile_mode` 只读**（本轮改）：
   这四个键的权威在主面板上，对话框写了会和面板互相覆盖。现在置灰 + 一行说明
   （"请到主界面「分块」设置"），值仍然照文件显示。
   ⚠️ 副作用：`tile` 为真时 `image_size`（Size 下拉）会被 `_sync_size_enabled()`
   连带置灰——这是原有逻辑（勾了分块后 image_size 只影响验证缩放），不是新问题。

## 三、怎么判断一个新写入者危不危险（三步）

1. 搜 `open(<路径>, "w")` 或 `json.dump(`；
2. 看它写的键数是不是等于"这份文件的全部键"：
   - **等于** → 全量覆盖。要么它真的拥有整份文件（如 `.task_history.json`），
     要么它在抹别人的键（如那个对话框）；
   - **小于** → 合并写。还要确认它是**先读后改**（读-改-写），否则就是"少写一半"。
3. 看函数体里有没有 `os.replace`：没有就是非原子，写到一半崩溃会留下半个 JSON，
   **而读侧往往没有容错** —— 半截文件 = 整份配置作废。
