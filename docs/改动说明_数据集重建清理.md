# 重建 YOLO 数据集前必须清空旧产物（否则 mAP 虚高）

日期：2026-11-16
关联：`docs/改动说明_检测导入直通训练.md`（同一天的检测链路）

## 1. 现象

`build_yolo_dataset()` 把图片按 base 名拷进 `yolo_dataset/images/train|val/`，
拷贝语句是：

```python
dst_img = output_dir / "images" / subset / img_path.name
if not dst_img.exists():
    shutil.copy2(img_path, dst_img)      # 已存在就跳过
```

全文件没有任何 `rmtree` / 清空逻辑 —— **旧副本永远不删**。

而划分是 `random.seed(42)` + `shuffle(按文件名排序的列表)`：

| 改动 | 列表长度 | 划分结果 |
|---|---|---|
| 什么都没变，重训 | 28 → 28 | 完全相同 |
| 补了图 | 28 → 29 | **置换整体改变，大面积换边** |
| 删了图 | 28 → 28-1 | 同上 |

换边之后，某张图这次被分到 `val`，上一轮留在 `train` 的那份不会被删 ⇒
**同一张图同时出现在训练集和验证集**。模型训练时见过它、验证时又考它，
mAP 会明显偏高，而界面上一切正常 —— 这比"划分不生效"危险，因为它让人**相信**一个假的数字。

删图方向同样有问题：工程里已经删掉的图，旧副本还在训练集里继续被训练。

## 2. 为什么这个问题差点被一条"看着很合理"的测试放过

上一轮提的测试是"改动某张图的标注内容后重建，断言不重叠"。**它是空转的**：

- 列表是 `sorted(annotated, key=lambda x: x[0].name)`；
- 改标注内容**不改变文件名集合** ⇒ 列表一模一样 ⇒ shuffle 结果一模一样 ⇒ 划分不变。

更进一步，就算改成"补一张图"，也**不保证**会重排。实测（seed=42, val_split=0.2）：

| 原张数 | 补一张后 train 集合是否变化 |
|---|---|
| 5 / 10 / 20 | **不变**（新的那张直接落到 val） |
| 7 / 12 / 15 / 28 … | 变 |

所以测试里必须**先证明前提成立**（本文件的 `_assert_split_changed()`），
前提消失就大声失败，而不是静默变绿。

## 3. 修法

`detection/dataset.py` 新增 `_wipe_previous_dataset(output_dir, project_dir)`，
在划分算完、建目录之前**整个删掉**上一轮产物（`images/`、`labels/`、`data.yaml`
一起清，避免新旧口径混用）。返回删掉的文件数，进 `build_yolo_dataset()` 的返回值
`removed_files`，界面上顺手打一行：

```
已清理上一轮数据集：120 个文件（避免新旧副本混用）
```

三条护栏（`output_dir` 传错一个参数就能把源图删了，必须挡）：

| 情况 | 行为 |
|---|---|
| `output_dir == project_dir` | `ValueError`（"不能是工程根目录"） |
| `output_dir` 是工程的**上级**目录 | `ValueError`（"不能是工程的上级目录"） |
| 目录非空、但没有 `images`/`labels`/`data.yaml` | `ValueError`（"不像构建出来的数据集"） |

清理失败（`PermissionError` 等）**转成带说明的 `RuntimeError` 抛出**，不用
`ignore_errors=True`：上一次训练的 DataLoader 可能还占着文件，此时静默继续会变成
"看着重建了、其实还是旧的"，比不清理更难查。

## 4. 连带修的一处：检测训练连点两次

清理一上线，"两份训练同时跑"就从"抢显存"升级成"互相删数据集"：
第二份重建时会把第一份正在读的 `yolo_dataset/` 删掉。

而 `_start_det_training()` 是**直接 `threading.Thread(...)`**（走队列的是分割训练），
连点两次就真的起两个线程。现在加了 `_det_training_running` 标志：

- 已在跑 → 弹一句"上一次训练还在跑"，**不起第二个线程**；
- 训练结束（`_on_det_training_done`，由 `__DET_TRAINING_DONE__` 信号驱动）复位；
- 线程都没起来时也复位，别把按钮锁死。

## 5. 测试（`tests/test_det_dataset_rebuild.py` 8 条 + `test_det_import_ui.py` 1 条）

| 用例 | 守什么 |
|---|---|
| 首次构建：文件数 == 报告数 | 方案 B，确定性最强 |
| 同数据重建两次：不重复 | 清理跑了、且没把新数据删掉 |
| ★ 补图后重建：不重叠（12 张，**含前提自检**） | 方案 A |
| ★ 删图后重建：旧副本被清掉 | 删图方向的残留 |
| ★ 清理失败必须抛错 | 真把文件 `open` 住造失败，不 patch `rmtree` |
| 护栏 ×3 | 根目录 / 上级目录 / 不像数据集 |
| ★ 检测训练连点两次被挡下（`test_det_import_ui.py`） | 并发护栏 + 结束后复位 |

## 6. 变异测试（7 条，全抓到）

| 变异 | 被哪条抓到 |
|---|---|
| 完全不清理（回到修复前） | 同数据重建两次 / 补图重建 |
| 清理失败改成 `ignore_errors=True` | 清理失败必须抛错 |
| 去掉"工程根"护栏 | 护栏：工程根（抛的不是 ValueError） |
| 去掉"上级目录"护栏 | 护栏：上级目录（信息不是这条） |
| 去掉"不像数据集"护栏 | 护栏：不像数据集 |
| 去掉训练并发护栏 | 连点两次（仍起了线程） |
| 训练结束不复位标志 | 连点两次（标志没复位） |

**这一轮我漏了 4 次，全是"测试自证"，记下来当反面教材：**

1. `ignore_errors` 那条 —— 测试 patch 了整个 `shutil.rmtree`，把参数差异一起屏蔽了。
   改用真 `open()` 占住文件造失败才抓得到。
2. "上级目录"护栏 —— 根本没有用例。
3. 并发护栏的复位 —— 我在 `finally` 里先把标志清了，后面那条断言永远为真。
4. 更早的"补图后不重叠"，用了 10 张 —— 实测 5/10/20 张时补一张图划分**根本不变**，
   用例空转（靠新加的 `_assert_split_changed()` 当场抓出来）。

## 7. 影响面

- **首次训练**：`removed_files = 0`，行为与以前一致；
- **K 折**：每折用 `yolo_dataset_fold{i}`，各自清理，互不影响；
- **不做**：划分语义仍是"自动留 20%"，不读 `train_test_split.json`（用户确认先不动）。

## 8. 顺手记录：`train_test_split.json` 的现状（未改）

- 分割（`training/dataset.py`）和分类（`classification/dataset.py`）**都认**它；
- 目标检测**不认**，自己随机切 0.2；
- 用户这个工程里 28 条全是 `train`（没有 val）。若真按它执行，验证集为空，
  YOLO 没地方算 mAP —— 所以"自动留 20%"本身是躲开了死路。
  真正不佳的是**没有提示**：界面划分了，检测训练不认，日志也不说。
