# 图片列表「标注」数翻倍：同一批标注被算了两次

日期：2026-11-16
现象：**"这张图我就 10 个字符，为啥列表显示标了 20 个？"**

## 1. 根因

检测工程的标注由**两份文件**描述同一批框：

```
images/<base>.json        labelme 原始标注（「导入标注」时落在 images/ 里）
images/<base>_det.json    平台检测标注（由上面那份转出来，训练只认它）
```

`_filter_images` 的统计对两份都累加：

```python
if _det_exists:   shape_count += len(det_boxes)      # 10
if _json_exists:  shape_count += len(json_labels)    # 再 +10  ← 重复
```

于是 10 → 20。**不是重复画框，是重复计数**——`_det.json` 里确实只有 10 个 annotations
（按 `(类别, bbox)` 去重后仍是 10 组，0 组重复）。

## 2. 真实工程的数据（复核用）

```
有 _det.json 的图：28（其中 28 张同时有 labelme .json）
检测框总数：300      labelme 形状总数：300
修复前 Blocks = 600（两份相加） → 修复后 300
```

## 3. 影响面

| 位置 | 现象 |
|---|---|
| 图片列表「标注」列 | 10 → 20 |
| 底栏 `Blocks:` | 300 → 600 |
| 筛选表达式「标注块数」（`core/filter_expr.py:62`） | 按数字比较时会误判 |
| **训练 / 数据划分** | **不受影响**：`build_yolo_dataset()` 只读 `_det.json`，`get_annotated_count()` 也是 |

> **更正（2026-11-16，复核指出）**：初版把「底栏『已标注 N』」也列进了受影响清单，**这是错的**。
> `total_annotated` 是按**张**累加的（`if has_ann: total_annotated += 1`），
> 只有 `total_shapes` 按**块**累加。所以 `Ann: 28` 从来没翻过倍，修完也不会变。

## 4. 修法

`_filter_images` 的统计改成**只认一个来源**，优先级：

```
_det.json（检测侧权威）  >  labelme <base>.json（分割/未转换态）  >  掩膜类别数
```

```python
if _det_exists:        ... # 检测框
elif _json_exists:     ... # labelme 形状（原来这里是 if，两份都算）
elif _mask_has_content: ...
```

顺带修掉一个潜在错：原来的 `elif _mask_has_content: shape_count = _mask_classes`
会把前面累加的检测框数**覆盖**掉；改成同一串 `if/elif` 后不会了。

### ⚠️ 语义：`_det.json` 存在即为准，空文件 = 0 个框，**不退回 labelme**

```python
if _det_exists:        ← 只要文件在，labelme 那支永远不走
elif _json_exists:
```

极端情况（实测）：labelme 有 3 个形状、`_det.json` 合法但 `annotations: []` → 列表显示 **0**。

**这不是 bug，是刻意的**：`_det.json` 是检测侧的权威，空就是"这张图真的没有框"
（用户删光了，或者本来就是良品）。退回 labelme 会把用户**删掉的框复现回来**，那是更坏的结果。

导入侧也堵住了静默丢数据：`_rebuild_det_for_imported()` 会打
`⚠️ 非矩形 shape 被跳过 {'polygon': 3}`，不会悄悄少框。

**别看到 `elif` 就以为是漏判的 bug 又改回 `if`。**

## 5. 测试（`tests/test_ann_count_source.py`，5 条）

| 用例 | 守什么 |
|---|---|
| ★ 两份文件都在（各 3）→ 算 3、Blocks 6 | 用户报的那个 bug |
| ★ 列表「标注」列与内部计数同源 | 别只在数据层修好、界面还显示旧值 |
| 只有 `_det.json` → 3 | 正常检测工程 |
| 只有 labelme JSON（分割）→ 3 | 没把分割那条路带偏 |
| ★ `_det.json` 3 + labelme 5 → 报 3 | 优先级（不是相加、也不是只读 json） |

## 6. 变异测试（3/3，但第一版漏了）

| 变异 | 结果 |
|---|---|
| 恢复成两份都累加 | 抓到（6 ≠ 3） |
| 优先级反转 | 抓到（det-only 变成 0） |
| 底栏 Blocks ×2 | 抓到（12 ≠ 6） |

**第一版"恢复成两份都累加"没抓到**：用例在**预热完成前**就断言了。
首轮建表时 `_allow_decode` 还是 False（后台掩膜统计没跑完），labelme JSON 分支被
整段跳过 —— 那一刻统计只有 `_det.json` 的数量，bug 看不见；等预热完成
`_on_mask_stats_ready` 会**补刷一次**列表，那时才会翻倍。

现在 `open_project(wait_warm=True)` 会等
`_mask_stats_ready_gen == _project_gen`（预热+补刷完成）再断言。
以后写这类"跨两轮刷新才稳定"的统计用例，都要先等到那一轮。

## 7. 已定案：空 `_det.json` 算「已标注」，列表显式显示 **0**

`det 空 + labelme 有框` 时，改后 `shape_count = 0` 而 `has_ann` 仍是 True
（`_det_exists`），于是列表标「已标注」但块数是 **空白** —— 看着和"根本没标"一模一样，
而 `Annotated Only` 又把它算作已标注，两边矛盾。

**产品口径（2026-11-16 确认）：空标注 = 人已经过目、确认这张没有缺陷（良品图）。**
所以：

- `has_ann` 语义**不动**（文件在即已标注），筛选与训练负样本口径不变；
- 列表「标注」列：`shape_count == 0` 且 `has_ann` → 显示 **`"0"`**，
  并带 tooltip「空标注：标注文件在、0 个框（通常表示「已确认无缺陷」）」；
- 真正没标注的图（既无 `_det.json` 也无 labelme）→ 仍然留空，不显示 0。

这样"0"和"空"是两种明确的含义，不用再靠猜。

对应代码：`_render_page()` 里 `_shape_text` 的三段分支 + `col == 4 and val == "0"` 的 tooltip。
测试：`test_ann_count_source.py` 的「空 _det.json：显示 0、算已标注、不退回 labelme」
与「真没标注的图留空（不显示 0）」。

## 8. 没做

- **没有删 `images/*.json`**：它是「导入标注」的原件，删了就没法回溯来源。
  真要瘦身应另做一次"归档到 labels/"，不在这次范围内。
- 训练侧完全没动（本来就没读错）。
