## 1. `build_yolo_dataset()` 遇到坏 `_det.json` 直接炸（P1，已修）

### 改之前

```python
# 扫描阶段（收集类别）
try:
    with open(det_json) as jf: data = json.load(jf)
    for cat in data.get("categories", []): ...
except Exception:
    pass                       # ← 坏的能走过去

# 转换阶段
def convert_pair(img_path, det_path, subset):
    with open(det_path) as f:
        data = json.load(f)    # ← 没有 try
```

实测（4 张图，`img3_det.json` 坏）：

```
直接抛 JSONDecodeError: Expecting property name enclosed in double quotes: line 1 column 3 (char 2)
异常里有没有指明是哪张图？  'img3' in str(e) = False
```

**300 张图坏一张，点"开始训练"就失败，报 `line 1 column 3`，不告诉文件名。**
而 `.bad` 留档只在**用户点开那张图**时才触发 —— 直接点训练永远等不到。

### 改之后

- **扫描阶段就判定**：解析失败的文件进 `corrupt` 列表，**不进 `annotated`**
  ⇒ 既不参与划分，也不会被拷进 `yolo_dataset/`（只有图没有 label 会被 YOLO
  当成"无目标的负样本"，那比直接报错更坏）。
- 训练继续，返回 `skipped_corrupt` / `skipped_corrupt_detail`；
  界面日志打一行，**指名文件**：

  ```
  ⚠️ 3 个标注文件损坏，已跳过（不参与训练）：img3_det.json、img17_det.json、…
  　—— 修好后重训，或从 images/*_det.json.bad-* 恢复
  ```

- 全部坏掉时抛 `RuntimeError`，消息里带文件名（不是裸 JSONDecodeError）。
- `convert_pair` 外面仍包一层：走到那里多半是**图片本身坏了**（PIL 打不开）
  或写盘失败 —— 异常统一转成带文件名的 `RuntimeError`。

顺带确认（复核者提的）：`.bad-2026…` 后缀既不在图片扩展名里、也不等于
`stem + "_det.json"`，所以留档文件不会污染训练集。

## 2. 「预测转标注」入口（补回 1 步工作流）

上一轮把单图推理改成"只进预测层"之后，"跑一遍模型再微调"从 1 步变 3 步。
检测工具栏新增一个按钮（工具行最右，虚线框 + 对勾图标）：

```
追加**本图**预测框 → 标注，已有框保留，同位置（IoU ≥ 0.5）跳过，可整体撤销
```

### 为什么不直接调 `convert_result_to_annotation`

复核建议走它、理由是"有版本快照可回滚"。**这个前提不成立**，我核过：

```
annotation/version_manager.py:8   .versions/<base>_v<ts>.json
annotation/labelme_io.py:8         get_json_path(image) = <base>.json   ← labelme 原件
```

`.versions/` 快照的是 **labelme 的 `<base>.json`**，不是 `<base>_det.json`。
所以 `convert_result_to_annotation`（内部 `_save_boxes` 直接重写 `_det.json`）
对检测标注**既没有版本快照、也不进 BoxManager 的撤销栈**，点错了只能手改回去。

改成走 `BoxManager`：

- 新增 `add_boxes(items)`：**一次快照 + 一次写盘**（`add_box` 改为它的单项特例）。
  一次 Ctrl+Z 整体回退，而不是按框回退 30 次；写到一半中断也不会留下半个标注。
- 去重用 `annotation.convert.box_iou` + `DEFAULT_TAU`（0.5），既有标注之间也比、
  本次收下的预测之间也比。
- 采纳后自动把预测层关掉（否则预测和标注完全重叠，看不出"已经变成标注了"）。
- 批量（按标记）那条路仍走 `convert_by_mark`，不动。

## 6. 变异测试 8/8

| 变异 | 被哪条抓到 |
|---|---|
| 坏的也进训练集（回到 `except: pass`） | 坏标注：跳过并指名 |
| 不返回 `skipped_corrupt` | 同上（"没报告是哪张文件坏了：[]"） |
| 去掉 convert 的带名异常 | 同上（裸 `JSONDecodeError` 冒出来） |
| 全坏时错误不带文件名 | 全坏时抛错要带文件名 |
| `add_boxes` 变回逐框快照+写盘 | 一次撤销（撤销后不是 3 个） |
| 转标注不去重 | 重复点翻倍了：7 |
| `cfg_path` 忽略环境变量 | test_test_isolation |
| 主窗配置路径手拼回去 | 主窗配置路径落在隔离目录 |

**变异脚本自己也修了一次**：原来判据是 `退出码非零 and 有 FAIL 行`，
于是"进程非零退出但没打 FAIL 行"（崩在断言外）被误报成"漏了"——
第 ⑧ 条第一次就是这么被冤枉的。现在只要**退出码非零**就算抓到，同时把那句
"没有 FAIL 行"标出来让人去核。另有一条变异本身括号不配对（语法错），
也算"无效"而不是"漏"——**变异脚本的语法守卫和判据都得先可信**。

## 7. 影响面 / 没做

- 训练现在会**跳过**坏标注并继续。若你想"坏一个就整体不训"，改成 `raise` 即可，
  但现场更常见的是"先练起来，坏的后面补"。
- 「预测转标注」只处理**当前图**；批量仍走「按标记转标注」（`convert_by_mark`）。
- `AITP_TEST_CFG_DIR` 只影响**仓库根**的配置；项目内的配置（`project.json`、
  `class_labels.json`）本来就在临时工程目录里，不受影响。
