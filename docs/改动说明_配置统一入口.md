## 一、先把"为什么"说清楚：一个坏字段能拖垮整份配置

改之前 `MainWindow._load_panel_train_settings()` 长这样：

```python
self.epochs_spin.setValue(int(s.get("epochs", 200)))     # ← "abc" / null 直接抛
self.early_stop_spin.setValue(int(s.get("early_stop_patience", 0)))
...
except Exception:
    pass                                                # ← 整段静默放弃
```

用户手改一次 JSON（`"epochs": "200 次"`），或者某个版本把字段写成字符串，
`int()` 就抛异常 → 被最后那个 `except: pass` 吞掉 → **后面所有字段都不再加载**。

结果是面板一半是旧值、一半是文件值，关窗时又被原样写回去 ——
用户只会说"我的设置又没保存上"，而日志里一个字都没有。

## 二、`core/settings.py` 做了什么

把配置声明成**一张表**（`SCOPES`），读取时逐字段校验：

| 情形 | 处理 | 是否算错误 |
|---|---|---|
| 键缺失（老文件没有新键） | 补默认值 | **否**（否则每次升级刷一屏告警，真问题被淹） |
| 类型不对（`"abc"` 当整数） | 该键退回默认值，其余照常加载 | 是，报 `invalid` 并指名键 |
| 超出范围（`epochs: 0`） | 夹到边界（保住用户意图） | 是 |
| 未知键（新版本写的） | 原样保留，`save` 时不丢 | 否 |
| 文件不存在 | `not_found`，`value is None` | 否（`benign`） |
| JSON 坏了 | `corrupt`，`value is None` | 是（可分辨） |
| 读不了（权限） | `io`，`value is None` | 是 |

返回值接 `core/result.py`（P0-1），`code` 能区分五种情况，
`message` 形如 `epochs: 要整数，给的是 str '200 次'`。

对外只有五个函数：`schema / defaults / validate / load / save`。

### 三条设计约束

1. **`validate()` 是唯一判据** —— `merge()` 只认它返回的 `Problem` 列表。
   变异「把 `merge` 里的 `bad` 换成空集、自己判」会让类型校验失效，测试当场红。
2. **缺失 ≠ 错误**（见上表第一行）。
3. **写入必须原子** —— 临时文件 + `fsync` + `os.replace()`。
   改前是 `open(p, "w")` 直接覆盖：写到一半断电就留下半个 JSON，
   下次启动走异常分支 ⇒ 全部按默认值来，用户所有训练设置一次丢光。

## 三、迁移了哪两个真实调用点（这是本轮的交付，不是"建了个文件"）

审核的验收标准是"**至少一个真实调用点从旧写法换过来**"，所以没有只写模块。

### 1. `_load_panel_train_settings()`

```python
res = _settings.load("train", self._train_settings_path())
if res.value is None:                    # 不存在 / 坏了 / 读不了
    if not res.benign:                   # 「不存在」是第一次启动，不刷日志
        self.log("[训练参数] %s —— 面板保持当前值" % res.code_text)
    return                               # ★ 一个控件都不动（与改前行为一致）
if not res.ok:                           # ★ 有字段被退回默认值，必须说出来
    self.log("[训练参数] %s —— 这些字段已退回默认值" % res.code_text)
s = res.value.values                     # 已补好默认值、类型已规范化
self.epochs_spin.setValue(s["epochs"])   # 默认值只有一份（schema），这里不再重复写
```

行为差异只有一处、而且是修 bug：**坏字段不再拖垮其它字段**。
文件不存在 / 配置损坏时仍然"一个控件都不动"，与改前完全一致。

### 2. `_save_panel_train_settings()`

收集面板值 → `_settings.save("train", s, path)`（合并写 + 原子替换）。
未知键原样保留（新版本写的字段不会被这个版本一保存就抹掉）。
顺手把 `except: pass` 换成"收集失败就记一条日志并放弃本次保存"。

## 四、顺带修掉一个测试污染（会直接影响用户）

跑完测试发现 `.train_settings.json` 的值变了（`epochs 150→200`、`batch_size 16→2`、
`tile_size 256→1024`）—— 不是我的改动丢字段（`unet_base` / `unet_depth` /
`augment_flags` 都在），而是 **`closeEvent` 会自动保存面板参数**，
而 `test_smoke_startup` / `test_load_progress` / `test_close_event` 都会关窗。

也就是说：**跑一遍测试，用户的训练设置就被换成测试窗口里的默认值。**
以前没人注意，是因为没人去 diff 这个文件。

修法：三个测试在关窗之前把 `_train_settings_path` 指到临时文件（已有 3 个测试
对 `.task_history.json` 用同样的办法）。改完实测：跑全套前后
`.train_settings.json` 的 md5 一致（`a0be5890…`）。

## 八、审核第二轮（2026-11-12）：`save()` 静默丢弃未知键 —— 改了

审核指出这段：

```python
for key, val in values.items():
    if key in sc.fields:
        payload[key] = val
# 只写 schema 键 + 原有未知键；传进来的未知键忽略（那是调用方打错字）
```

方向对，但**没留下任何记录**：`save({"epohcs": 200})` 会静默不写，
调用方以为保存成功了，下次读出来还是老值。**这和 P0-1 要治的"失败没语义"是同一个病** ——
既然我已经识别出"那是调用方打错字"，最该做的恰恰是告诉它。

### 1. 改法：`save()` 返回 `SaveReport`，不再只返回 `True`

```python
class SaveReport:
    written   # 真写进去的键
    ignored   # 传进来但 schema 没声明的键（多半拼错）

def save(...):
    ...
    return Result.success(SaveReport(written, ignored))
```

**没有往 `Result` 上加 `ignored_keys`**（审核给的另一种选择）：`Result` 是通用容器，
`ignored_keys` 只有配置才有意义，塞进去会让它变成一个越长越胖的杂物袋。
`save` 的 value 本来就该是"这次写入了什么"，用它自己的类型最干净。

### 2. 调用点把 `ignored` 写进日志

```python
rep = res.value
if rep is not None and rep.ignored:
    self.log("[训练参数] 保存时忽略了未声明的键：%s（键名拼错了？）"
             % ", ".join(rep.ignored))
```

这条路以后接剩下 6 组配置时最有用 —— 面板加了个控件、忘了在 schema 里声明，
保存时就会当场报出来，而不是等到"用户说设置没保存上"再查。

### 3. 为了让这条日志**测得到**，抽了一个方法

面板正常收集不会拼错，那条 `if rep.ignored:` 分支就永远走不到 —— 写了不验。
所以把收集逻辑抽成 `_collect_panel_train_settings()`（返回 dict / None），
测试里替换成"返回带 typo 的字典"，日志分支才真的被执行：

```python
w._collect_panel_train_settings = lambda: {"epochs": 12, "epohcs": 200}
w._save_panel_train_settings()
assert any("epohcs" in m for m in logs)
```

（这是本项目的第三次同类教训：**代码写了但没有任何路径能执行到它，等于没写。**
前两次是 `reset_view` 被同名覆盖、`validate()` 没接进执行路径。）

### 4. 验证

`test_settings.py` 23 → **24 条**：

- `★ save 把打错的键报在 ignored 里`：`ignored == ("epohcs",)`、`written` 含 `epochs`、
  文件里没有 `epohcs`、`res.ok` 仍为 True（打错键不该让整次保存失败）；
- `★ 面板：拼错的键写进日志`：真实调用点，日志里能找到 `epohcs`。

变异 4/4：

| 塞回的形状 | 结果 |
|---|---|
| `save` 不收集 `ignored`（永远空） | 两条都**红** |
| `save` 返回 `True` 而不是 `SaveReport` | 两条都**红** |
| `save` 把未知键也写进文件 | 两条都**红** |
| 调用方不打 `ignored` 日志 | 面板那条**红** → `★ 拼错的键没有被报出来（日志里找不到 epohcs）：[]` |

> 顺带：第一次做第 4 条变异时我把代码替换成了语法错误，那次"变红"不算数 ——
> 重新用 `if False:` 干净地只关掉日志分支，报错信息才是上面那条。
> **变异脚本把文件改坏时，测试也会红，但那证明不了任何事。**

### 5. 顺带统一了汇总行格式
