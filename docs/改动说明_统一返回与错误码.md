## 一、目标与验收标准

审核给的验收标准很明确：**不能是"加了个空壳模块但没人用"** ——
"至少有一个真实调用点从旧写法换过来了"，否则就是给清单打勾。

所以本轮不是只写一个 `Result`，而是**真把一个模块搬过去**，并让它的错误码产生
用户可见的价值。选中的是 `core/mask_stats_cache.py`（掩膜统计的工程级 sidecar 缓存），
理由：它原来把**四种不同的失败**压成同一个返回值，是"失败没有语义"最典型的样本。

## 二、动手前：那个模块原本吞掉了什么

```python
def load(project_dir):
    try: ...
    except Exception: return {}          # 文件不存在 / JSON 坏 / 权限错 → 全一样
    if ... version != VERSION: return {}  # 版本不符 → 也一样
    if ... not isinstance(entries, dict): return {}   # 结构不对 → 也一样
```

后果很具体：缓存文件被写坏、或者平台升级后版本号变了，**用户只感觉"这次打开工程慢了 6 秒"**，
日志里一个字都没有。反过来，把"还没建过缓存"（正常）和"缓存坏了"（异常）当成一回事，
也没法决定要不要提醒用户。

## 三、`core/result.py`

```python
class ErrCode:      # 字符串常量，不是 Enum：日志/JSON 里直接就是 "corrupt"，能 grep
    OK / NOT_FOUND / CORRUPT / VERSION / IO / INVALID / CANCELED / UNKNOWN
    BENIGN = (OK, NOT_FOUND)     # "本来就没有"，调用方不该报警

class Result:
    code, value, message, where
    ok        # 属性，不是字段 —— 构造不出 ok=True 同时 code=IO 的对象
    benign    # 失败是否属于"本来就没有"
    code_text # "corrupt / load: Expecting ..."，一行给日志
    __bool__  # 等价于 ok ⇒ 老代码 `if save(...)` 不改也能跑
    success() / fail() / unwrap_or() / unwrap() / raise_if_failed() / as_dict()

@guard(ErrCode.IO, where="...")   # 给"会抛异常的老函数"套一层，函数体不用改
```

三条设计约束（写在模块头部，别"优化"掉）：

1. **`ok` 是属性、不是字段** —— 字段只有 `code`，避免自相矛盾的对象。
2. **`Result` 可当真假用** —— 迁移可以一个文件一个文件来，不必一次改完 610 处 `except`。
3. **不带异常对象** —— 要能进日志/JSON；原始异常信息用 `message` 带一句。
   另外 `fail(ErrCode.OK, ...)` 会**当场纠成 UNKNOWN**（那是笔误，不能造出矛盾对象）。

## 四、真实迁移（这才是本轮的交付）

### 1. `core/mask_stats_cache.py`

| 情况 | 改前 | 改后 |
|---|---|---|
| 缓存文件不存在 | `{}` | `NOT_FOUND`（benign，正常路径） |
| JSON 语法坏 | `{}` | `CORRUPT` |
| 版本不符 | `{}` | `VERSION` |
| `entries` 结构不对 | `{}` | `CORRUPT` |
| 部分条目坏 | 静默丢 | 值照用，`message` 带「丢弃 N 条坏记录」 |
| 写盘失败 | `False` | `IO` + 原因 |

依然**绝不抛异常**（缓存是加速手段，坏了就退化成全量重算），
但"为什么退化"现在带得出去。取值用 `.unwrap_or({})`，失败时 `value` 是 `None`。

### 2. `ui/main_window.py`（唯一的调用点）

```python
_cache_res = _msc_load(project_dir)
side = _cache_res.unwrap_or({})
if not _cache_res.benign:                 # 坏文件 / 版本旧 —— 值得说一句
    self.log_signal.emit("[掩膜缓存] %s —— 本次全量重算" % _cache_res.code_text)
...
_save_res = _msc_save(project_dir, side)
if not _save_res.ok:
    self.log_signal.emit("[掩膜缓存] 写盘失败：%s" % _save_res.code_text)
```

用户从此能在日志里看到「掩膜缓存 corrupt / load: Expecting value ... —— 本次全量重算」，
而不是莫名其妙地慢 6 秒。

## 五、验证

- `tests/test_result.py` **11 条**：`ok`/`code` 不自相矛盾、`bool()` 与 `ok` 一致、
  `fail(OK)` 被纠正、`benign` 判定、`unwrap`/`unwrap_or`/`raise_if_failed`、
  `guard` 三种情形（异常→码、普通返回→success、已有 Result→**不许包第二层**）、
  默认 `where`、以及 **★ 真实模块已用上**（跑 `mask_stats_cache` 的三个码）。

  （`not_found` / `corrupt` / `version` / `io` 各一条）—— 这是"迁移"和"只是编译通过"的区别。
- 变异检验（临时副本，改完还原）：把 `load` 改回"不存在也当成功"、`fail(OK)` 不纠正、
  `guard` 给 Result 再包一层、坏 JSON 报 `not_found` —— **4/4 对应用例变红**。
- 全套回归 **11 个脚本 87 项全绿**。

## 六、请重点核对

1. **失败时 `value` 是 `None`**（`Result` 的统一语义），不是空 dict。
   现有唯一调用点已用 `.unwrap_or({})`；将来谁直接 `.value` 取值要记得这条。
2. **`ErrCode` 用字符串常量而不是 Enum** —— 与 `task_queue.TaskState`（Enum）风格不同。
   理由写在模块里：这里只要一个稳定的短字符串进日志，不需要比较/持久化语义。
   如果认为项目该统一用 Enum，改起来只动这一个文件。
3. **`guard` 只兜 `Exception`**（不含 `BaseException`）—— `KeyboardInterrupt` /
   `SystemExit` 不该被吞成错误码。
4. **只迁移了一个模块**。其余 609 处 `except` 没动，这是 P0-1 的既定范围（零侵入）。
   下一批建议按"失败最需要被看见"的次序挑：`ui/task_queue._save_history`（静默吞异常）、
   `ui/class_table` 的两处 JSON 读取。
