# 画布 Space / Ctrl+Space：显示开关、入口一致性、全局空格不抢输入框

日期：2026-11-16
涉及：`annotation/mask_editor.py`、`ui/main_window.py`

## 1. 症状（用户口径）

在目标检测工程里按空格 / Ctrl+Space，有几个不对劲：

1. 先点图片列表、再按空格 —— **没反应**（必须点一下画布才行）。
2. 按 Ctrl+Space 框是关掉了，但画布左下角那行状态**仍显示 `Annot:ON`**。
3. 三视图工程里在主画布按空格，参考窗不跟着变。
4. 按住空格不放，状态**反复闪**，松手停在哪看运气。

## 2. 根因

| # | 根因 |
|---|---|
| 1 | 空格只在 `AnnotationCanvas.keyPressEvent` 里处理，画布没焦点就收不到。主窗 `eventFilter` 只兜了分类模式（`_cls_mode`），检测模式没兜。 |
| 2 | `status_info_text()` 的 `ann_status` 无条件读 `_show_annotation`；而检测模式画框看的是 `_show_annotation_boxes`（`paintEvent` 里 `det_overlay.paint(show_annotations=...)`）。同一个函数里 `pred_status` 早分了支，这里漏了。**检测模式下 `Annot:ON` 是永远不动的假显示。** |
| 3 | `keyPressEvent` 的 Space 分支是内联副本，末尾只有 `self.update()`，**没有 `view_changed`**；按钮入口 `toggle_prediction_visibility()` 会发。多视图参考窗靠 `view_changed` 即时刷新（代码注释明说"不再依赖轮询"）⇒ 键盘入口看着"慢一拍"。 |
| 4 | 空格分支与 Ctrl+Space 分支**都没判 `isAutoRepeat()`**。同文件的 `_is_ctrl_alt_toggle()` 和分类模式的 `eventFilter` 都判了。 |

## 3. 修法

- `status_info_text()`：有 `_det_overlay` 读 `_show_annotation_boxes`，否则读 `_show_annotation`。
- `keyPressEvent`：两个空格分支都加 `if not event.isAutoRepeat():`；
  Space 分支不再内联复制逻辑，**直接调 `toggle_prediction_visibility()`**
  （文件里那句"两处入口必须都走同一个方法"就是为这种情况写的）。
- `eventFilter`：加 `_focus_is_text_input()` / `_space_should_be_ours()`，
  把检测模式接进全局兜底，并按修饰键分流（纯空格 = 预测框，Ctrl+Space = 标注框）。

## 4. ⚠️ 全局兜底必须带焦点守卫（这一节是重点）

**第一版修法被驳回**：当时想"像分类模式那样在 `eventFilter` 里兜住空格"。
问题是这个过滤器装在 `QApplication` 上 —— **等于接管全应用的按键**，而老版本
只判 `_cls_mode`、**不看焦点在哪个控件上**：

```python
QApplication.instance().installEventFilter(self)          # main_window.py:230
if KeyPress and Key_Space and not isAutoRepeat and self._cls_mode:
    self._toggle_heatmap(); return True                   # 5289
```

后果（实测，不是理论风险）：分类工程开着时，新建工程对话框里打 `'NG part'`
会变成 `'NGpart'`，还顺手把背后的热力图切了一刀。工作区里 `Classify` /
`MixedClassify` / `混合分类` 都是分类工程。

所以这轮：

- `_space_should_be_ours()` 先排除三种情况：**自动重复**、**焦点在输入控件**
  （`QLineEdit` / `QTextEdit` / `QPlainTextEdit` / `QAbstractSpinBox` / 可编辑
  `QComboBox`）、**有模态对话框**；
- 修饰键分流：`mods == Qt.NoModifier` 才算"纯空格"。老代码没分，分类模式下
  **Ctrl+Space 也被吃掉**（切热力图）；
- 检测模式下，焦点不在画布时空格 / Ctrl+Space 也能用（①的收益）。

分割模式**没动**：空格仍只认画布内，保持原有语义（这次只修被报告的问题）。

## 6. 变异测试（9 条，全抓到）

状态行改回一刀切 / Space 改回内联副本 / 去掉两个 autoRepeat 判断 /
去掉输入框守卫 / 去掉模态守卫 / 去掉检测模式全局分支 / 去掉全局 Ctrl+Space 分支 /
修饰键不分流 —— 每条都让对应用例变红。

**这一轮又栽了一次"红得不对"：**

- 模态守卫那条变异**第一版没抓到**。原因是用例先把焦点留在输入框上就断言
  `_space_should_be_ours() is False` —— 输入框守卫替模态守卫挡了枪。
  改成：模态框里先放一个按钮让默认焦点落在非输入控件上，并**断言
  `_focus_is_text_input() is False`** 作为前提，再断言守卫返回 False。
- 顺带发现焦点会残留：上一条用例删掉控件后，焦点落回主窗搜索框。
  统一加了 `give_focus()`（先 `clearFocus` 再 `setFocus`，**并断言真的挪到位**）。

## 7. 没做 / 待定

- **备用快捷键**：Ctrl+Space 如果被中文输入法当"中英切换"吃掉（Windows 默认），
  这个功能在现场就等于不可用。建议加 `Ctrl+Shift+Space` 作备用
  （`Alt+Space` 是 Windows 的系统窗口菜单，别用）。**等确认后再加。**
- 分割模式是否也全局化：本次不动。
