一、本次最值得看的 7 条结论

1. AI 工具是"插件"，接口契约完整暴露

iCogtiveFlow_AiTool.dll 导出 311 个符号，构成一个完整的工具插件框架：CHhAiTool（基类）/ CHhAiToolAPI（190 个方法的流式 API）/ Context / DataMgr / Metrics / Recordable。

22 个工具 DLL 各自只是一个薄壳（0.24–0.87 MB），真正的算法在 VisualEditor_IAL.dll（44.9 MB）。我们的 DL Studio 目前是单体，这是最值得学的一刀。

2. 参数体系用"区间"统一表达

所有后处理过滤参数的类型都是 IAL::AiInterval 的 vector：areaThreshold / angleThreshold / grayThreshold / heightThreshold / widthThreshold / scoreThreshold / radius / centerRegionRadius。

手册印证："必须在这两个值中间才会被保留"——统一的上下限区间 + 排序 + 最大检测数，比"单阈值"表达力强得多，且天然可复用到标注/推理/评估三处。

3. 参数自适应搜索已产品化，且有专门 API

initAutoDLHandle / releaseAutoDLHandle / getAutoDLRecommendDataAugment / getAutoDLRecommendTrialNumber / getAutoDLResult / autoDLDataAugment。

流程：设试验轮数（推荐 10）→ 添加待搜参数并给范围 → 开始 → 做参数重要性分析 → 一键应用回增强参数。这正是我们上次 P0 清单里的那一项。

4. 训练流程本身是一张图 + 异步

iCogtiveFlow_Train.dll 里出现 dmd::NodeModel / dmd::NodeSetBase / dmd::CanvasModel / HHRuntimeNode / HHGraphBase，以及 ivalue::Future / ivalue::Await（LibTorch JIT 的异步原语）。

即：训练管线不是硬编码 if-else，而是节点图 + Future/Await 的异步执行。这是支撑"工具链接"的底层能力。

5. 模型库按"任务 × 尺寸档"成矩阵

nets/ 下 27 个 预训练模型：pretrained_dl_{ad|cl|cl3d|clmixed|sg|sg3d|sgmixed|od|od3d|rod|ed|isg|kpd|ocr|ia|mcl|msg}_{tiny|small|medium|large}.net，体积 5.7 MB（sg_tiny）→ 150 MB（ocr_small）。

手册里的"网络大小 小/中/大"就是一个模型文件对应一个档，用户不用懂网络结构，只选档位。容器格式 magic = 0x12345678，是自研格式，不是 TorchScript。

6. 推理与模型优化是两个独立动作

"模型管理"里可选优化模型（选设备 → 选保存路径 → 确认），对应其依赖栈里的 TensorRT 10 + OpenVINO；另有修改推理块大小以降低大图推理耗时。

依赖清单同时含 LibTorch(c10/cudnn9/cublas12) + TensorRT(nvinfer_10/nvonnxparser_10) + OpenVINO(含 genai/多前端)——多后端推理，不是单栈。

7. 授权按"训练端 / 推理端"分权

手册明写：训练端（威步 CodeMeter）可训练+推理，推理端（深思数盾 Virbox，产品码 48503200 / 28506200）只能推理。

这是纯商业设计而非技术设计，但直接决定产品形态——我们若做 DL Studio 商业化，这套分权模型可以直接参考。

2.1 各工具 DLL 为什么这么"薄"

22 个工具 DLL 每个仅 0.24–0.87 MB，而算法库 VisualEditor_IAL.dll 有 44.9 MB。说明分工是：

iCogtiveFlowTool_<Name>.dll      ← 薄壳：UI 配置 + 参数校验 + 调用 API（~0.8MB）
        ↓
iCogtiveFlow_AiTool.dll        ← 契约定型：CHhAiTool / CHhAiToolAPI / Context / Metrics
        ↓
VisualEditor_IAL.dll (44.9MB)  ← 算法本体：namespace IAL
VisualEditor_CAL.dll (25.2MB)  ← 标定/几何
VisualEditor_ImageProcess.dll  ← 图像处理
VisualEditor_Metrology.dll     ← 测量
VisualEditor_GraphData.dll     ← 图形数据（图元模型）

五、训练模块的架构（iCogtiveFlow_Train.dll）

dmd::Node / NodeModel / NodeSetBase / CanvasModel / Community   // 训练节点图模型
HHRuntimeNode / HHGraphBase / HhSGRuntime                       // 运行时节点与图执行
ivalue::Future / ivalue::Await / ivalue::Object                 // 异步原语（LibTorch JIT）
c10::RRefInterface                                              // 确认链 LibTorch
Augmentation / AiDataAugmentSwitch                              // 增强配置
HHPose / HHMatrix / HHMat33D / HHCoordinateSys2D / 3D / HHCanvas2D  // 几何与坐标系统
HHCircle2D / HHCircleArc / HHCircleRing / HHCircleSector2D / AiRotRect / AiTextBox  // 图元

三条可借鉴：

  1. 训练管线图化：NodeSetBase（节点集合）+ CanvasModel（画布）+ HHRuntimeNode（运行态）是把"流程配置"与"训练执行"统一到同一套图模型上——这与我们讨论的"AI 工具链接（分割结果作为下游 ROI）"是同一个底座。
  2. 异步原语来自 LibTorch JIT：Future/Await 让"训练排队 + 推理并发"能自然实现（对应手册的"任务队列"）。
  3. 几何库独立成层：HHPose/HHMat33D/HHCoordinateSys2D/3D 说明他们从一开始就准备了标定与坐标系这一层——这正是我们抓 mm/px 定标和 2mm² 换算需要的底座。

7.1 它自己写在手册里的经验值（可直接对照我们的口径）

  • 分类适用判据：图片特征差异超过 30% 才适合做分类
  • 项目起步样本量：初始阶段每个类别约 50 张
  • 标注策略：先标一部分 → 先训一版 → 把输出导回标注做精细化修改（主动学习闭环）
  • Loss 判读：用"鱼缸曲线"形容——下降阶段=欠拟合，水平阶段=可用于检测
  • 实施方案要同时考虑 显存占有率与 CT（节拍）
  • 3D 大分辨率图：先截图再进工程，否则图一多会内存崩溃
  • 异常检测只标注 Normal/Defect，训练集必须全 OK；它不能精确测缺陷大小，要精确测量请改用分割

八、落到 DL Studio 的清单

8.1 P0（直接吃当前项目痛点）

  1. AI 工具插件化 + 契约层：抽 ToolAPI / ToolContext / ToolMetrics / ToolDataMgr 四个角色，工具只写"配置 + 调用"。架构级
  2. 指标收口成 Metrics 组件：按任务类型灌入（分类/检测/分割各一条 push 通道），统一出报表；替代当前散落的评估脚本。
  3. 区间型后处理过滤层：分数/面积/宽/高/角度/灰度/半径/中心半径，全部上下限区间 + 排序 + 最大检测数；不改模型就能调过杀漏检。
  4. 图像四态标记（正常/过杀/漏杀/存疑），且明确不入训练集。
  5. 参数自适应搜索：前置条件是先把增强算子做成同签名函数族。
  6. 分块训练/推理：块大小 + 宽高步长，配"大缺陷用大块、小图优先整图"的默认策略。
  7. 模型效果报表导出：模型信息 + 概率分数分布 + ROC + 结果清单（LTRB）。
  8. 几何与标定层独立：坐标系/位姿/矩阵/双轴 mm-per-pixel，撑住客户 2mm² 口径。

8.2 P1

  1. 预训练权重矩阵（任务 × tiny/small/medium）预置到安装目录，用户只选档位。
  2. 工具链接：上游分割/检测结果作为下游 ROI 或掩膜，多结果自动扩下游输入。
  3. 筛选表达式（字段 + 条件 + 值 + AND/OR + 语法校验）。
  4. 任务队列 + Loss 曲线随任务弹出、完成自动关闭。
  5. 智能标注（AI 预标注 + 二值化自动标注 + 阈值区间过滤 + 反转 + 多边形橡皮擦）。
  6. 训练流程图化（节点集合 + 画布 + 运行时节点），为多任务流水线留底。

8.3 P2 / 需商业决策

  1. 训练端 / 推理端分权授权（涉对外发布与成本，交 Arthur 拍板）。
  2. 软件多开（multiInstances/user_x）。
  3. 多后端推理抽象（LibTorch 训练 + TensorRT/OpenVINO 推理优化），当前我们只有 PyTorch 一条路。

九、不该照抄的部分

  • 不抄代码与接口命名：不要在我们的代码里出现 CHh* / HH* / IAL:: / dmd:: 这类命名，也不要照搬 CHhAiToolAPI 的方法名——法务上说不清，识读上也容易混淆。
