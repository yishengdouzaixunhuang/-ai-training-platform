# AI训练平台 · 使用说明

> 面向**操作员**：从新建工程到标完一片料，需要点的每一步。
> 开发者请看同目录的《开发文档.md》。

---

## 1. 启动

- 桌面快捷方式 **AI训练平台**（或 `E:\00-软件\ai_training_platform` 下用 `C:\aitp_venv\Scripts\pythonw.exe main.py` 启动）。
- 启动约需 12 秒（加载界面 + 模型），**别连点两次**，会开出两个实例、同时读写同一工程。
- 三视图工具（导入/训练/评估的向导式菜单）在便携版里的 **孚能三视图工具.bat**。

## 2. 界面分区

| 区域 | 作用 |
|---|---|
| 左栏 | 工程列表 / 图片列表（筛选、全选、右键导入 JSON） |
| 中间 | 预览区：漫反射（可标注）+ 形状图1 / 形状图2（只读参考，三窗缩放同步） |
| 右侧竖栏 | **参数管理 / 标注管理 / 模型管理 / 图像管理** 四个模块（文字竖排页签） |
| 底部 | 日志（`Ctrl+L` 显隐） |

右侧每个模块里是若干**区块**（左侧一条青色竖条 + 标题），**点标题即可折叠/展开**。

## 3. 标准流程

1. **新建/打开工程**：左栏 Projects 区双击工程名；新建用底部 `+ New Project`，
   选输入类型（单张 / 双视图 / **三视图**）。
2. **导入图片**：右键图片列表 → `Add Images…`；三视图工程选**按视图分组**的加图窗口，
   每个视图一个槽位。
3. **导入标注 JSON**：图片列表里选中这批图 → 右键 → `Import JSON for Selected...`
   - 类别表会**自动从 JSON 里发现类别**（不需要手工添加）；
   - 同时会把掩膜 PNG 生成出来（多视图只生成 `te_0` 的，三视图共用一张掩膜）。
4. **标注**：在漫反射窗口画掩膜。工具键：`B` 画笔 / `L` 直线 / `R` 矩形 / `C` 圆 /
   `O` 椭圆 / `P` 多边形 / `E` 橡皮 / `I` 忽略区 / `H` 平移；`1`~`9` 选类别；
   `Ctrl+Z` / `Ctrl+Y` 撤销重做；`Ctrl+S` 保存（编辑时也会自动存）。
   - `Ctrl+Space` 显示/隐藏**缺陷类别**；`Ctrl+Alt`（或 `Ctrl+Alt+I`）显示/隐藏**忽略区**。
   - 焦点在任意窗口都有效。
5. **划分数据集**：右侧「图像管理」→ 数据集划分 → `管理划分…`。
6. **训练**：右侧「参数管理」→ 训练参数 → `Start Training`。
   训练前先在「增强参数」里勾选增强方式。
7. **推理与后处理**：右侧「参数管理」→ 推理参数 → `Run Inference`；
   下面的**推理参数**按类别过滤连通域（分数/面积/宽度/高度/角度/灰度 + 孔洞填充/排序/最大个数）。
   - 上限填**负数 = 不限**；`Apply All` 把当前类别这组参数复制给所有类别。
   - 参数存在 `<工程>/inference_params.json`，单张推理和批处理**共用同一份**。
8. **看结果**：`Space` 开关预测层；右侧「标注管理」的 `结果` 区块是**逐块**统计
   （序号/类别/分数/面积/宽度/高度/周长/半径/平均灰度/交并比），排序跟随推理参数。

## 4. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| Class 表一行都没有 | 工程 `project.json` 的 classes 是空的 → 点 Class 表「刷新」，或右键图片列表批量导入 JSON（会顺带补类别） |
| 窗口2/3 的图比窗口1 偏上 | 已修（三窗视图矩形对齐）；若再现请截图反馈 |
| 标注看不见了 | 八成按了 `Ctrl+Space`（类别）或 `Ctrl+Alt`（忽略区），再按一次即可 |
| 推理结果为空 | 检查「推理参数」的面积下限是不是填太大（比如 100000） |
| 训练很慢 | GUI 里训练走的是 GPU（cu126 环境）；便携版是 CPU torch，别在便携版里训练 |
| 分割训练的验证集为空 | 没有 `train_test_split.json`，用「管理划分」生成一次 |

## 5. 算法指标（平台只对自己能客观测的东西负责）

平台内**只使用可客观复现的指标**，客户那边的人工质检口径（谁算漏检、谁算过杀）不写进本平台文档：

| 指标 | 定义 | 怎么测 |
|---|---|---|
| **缺陷召回率** | 标注里的缺陷实例，被模型报出来的比例 | `tools/eval_farasis.py`（含按尺寸分层） |
| **无缺陷误报数** | **没有任何缺陷的图**上，模型报出来的块数（理想 0） | 同上；`tools/infer_cell_farasis.py` 给整图口径 |
| 像素 IoU / mIoU | 分割本身的拟合程度（只用于横向比模型，不对应业务） | 训练日志 |

三条原则：
1. **同一工作点**上同时给"召回率"和"无缺陷误报数"——不允许用召回换误报。
2. 缺陷按尺寸分层看：**<16px 的缺陷是召回的主要缺口**（实测贡献 82.8% 的漏检）。
3. 平台侧压制误报的三个手段：**概率阈值 + 最小面积过滤**（推理参数）、
   **忽略区**（把"有特征但不是缺陷"的区域排除）、以及**训练数据覆盖**（见下）。

> ℹ️ 语义分割是**逐像素**判定：每张训练图里的 `background`(0 类) 就是"正常"像素，
> 数量极多，不存在"没有负样本"的问题。会出误报的真实原因是：
> ① 某些正常纹理在训练集里**从未出现过**（模型无从知道它正常）；
> ② 小尺度上正常纹理与缺陷难以区分；③ 阈值/后处理没有按"零误报"来选。
> 所以该做的是**让数据覆盖那些外观**（良品图可以，缺陷图里把这些区域标成背景/忽略区也可以），
> 而不是去"补负样本"（那是分类/异常检测的说法）。
