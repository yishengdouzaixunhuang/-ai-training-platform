# 坏 `_det.json` 不再把「打开工程」顶掉

日期：2026-11-16
来源：复核时的附带发现（不是 `ec14146` 引入的，是既有问题）

## 1. 现象

`images/<base>_det.json` 内容坏了（例如 `{ oops`）时，异常从 `BoxManager.load()`
一路冒到 `_open_project_by_name` 的兜底 `except`：

```
QMessageBox.warning(self, "Error", "Expecting property name enclosed in double quotes: line 1 column 3 (char 2)")
```

两处都不对：

1. 用户看到的是**原始 JSON 解析错误**，不知道发生了什么、更不知道该怎么办；
2. 此刻工程是**半开**的 —— 画布有预览图、`current_project` 已设、**图片列表是空的**。
   用户以为工程坏了。

## 2. 修法

| 位置 | 改动 |
|---|---|
| `BoxManager.load()` | `load_coco_json()` 包 try：失败按 **0 个框**处理，原因记进 `self.load_errors["annot"]` |
| `BoxManager.load_predictions()` | 同理，记 `load_errors["pred"]`，按"没有预测"处理 |
| `_load_det_annotations()`（UI） | 读 `load_errors`，打一行可读的日志 |

日志长这样：

```
⚠️ 该图标注文件损坏，已按 0 个框显示：字符-20261112 (82).png（JSONDecodeError: Expecting property name ...）
⚠️ 推理结果文件损坏，已按 0 个预测显示：xxx.png（...）
```

语义：**坏文件 = "这张图没有框"**，与空 `_det.json` 一致（见 `改动说明_标注计数去重.md` 第 4 节）。
不抛、不弹窗、不半开 —— 工程照常打开，列表照常有行。

## 3. 测试（`tests/test_corrupt_det_json.py`，5 条）

| 用例 | 守什么 |
|---|---|
| ★ 坏 `_det.json`：`load` 不抛、0 个框、记原因 | 加载点不炸 |
| 正常文件仍读到框 | 别把好文件也吞了 |
| 坏推理结果：`load_predictions` 不抛 | 同一条路的另一半 |
| ★ 带坏标注的工程能正常打开、不弹原始异常 | 端到端：列表有行 + 日志有话说 + 弹窗里没有 JSON 异常 |
| 对照组：正常标注仍是 3 个框 | 修坏文件没把好文件带偏 |

界面那条用 `w.log_signal` 抓日志、把 `QMessageBox.warning` 换成记录器，
所以"弹了原始异常"和"日志没说清楚"都会被抓到。

## 4. 变异（3/3 抓到）

`load` 的 `except` 换成别的异常类型（模拟"不吞"）/ `load_predictions` 恢复成直接抛 /
去掉界面那行日志 —— 三条都让对应用例变红。

## 5. 排除项：offscreen 下弹模态框会 segfault（**不是产品问题**）

复核复现时进程直接崩，用最朴素的对照排除了：

```
空 QMainWindow + QMessageBox.warning(off, "Error", "测试")  →  Windows fatal exception: access violation
```

是 **offscreen 平台弹模态框**的问题，与产品代码无关。**别按这个去改产品。**
（本文件的界面用例因此把 `QMessageBox.warning` 换成了记录器 —— 顺带也避开了这个坑。）
