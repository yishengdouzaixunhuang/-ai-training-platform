# 批量检测推理后「分数」「耗时ms」不回填（重启后必空白）

日期：2026-11-16
现象："推理完后，分数和耗时都没有回填"（结果列有数：10 / 14 / 15）

## 1. 两条独立根因

| 列 | 数据来源 | 为什么空 |
|---|---|---|
| 分数 | `self._img_conf[base]`（该图所有检出的**平均置信度**） | 检测那一支**从来没算过**。分割有（`<base>_prob.png`），检测只填了 `pred_count` |
| 耗时ms | `self._infer_times[base]` | 检测批量连**内存**里都没写；输出 JSON 也没有任何时间字段 ⇒ 重启必然空 |

两处都在 `_load_output_stats_async()` 里，检测那个 `elif f.endswith("_det.json")` 分支。

## 2. 修法（落盘 → 读回 → 上屏）

1. `flow/nodes/detection.py`（DetInfer）：给 `frame.meta["infer_ms"]` 记**纯推理**耗时
   （只包 `trainer.predict`，不含读图/存盘，与分割批量、单图同口径）。
2. `flow/nodes/output.py`（DetResultWriter）：`save_coco_json(..., meta={"infer_ms": ...})`。
3. `detection/coco_io.py`：`save_coco_json()` 新增 `meta=None` 参数，写进顶层 `"meta"`。
   **只写不读** —— `load_coco_json()` 完全忽略它，老文件/新文件互通。
4. `ui/main_window.py`：
   - `_load_output_stats_async` 检测分支：`mean(annotations[].score)` → `img_conf`；
     读 `meta.infer_ms` → `img_times`；
   - 耗时**只补内存里没有的**（`setdefault`）：本会话刚跑出的值更可信，别被上一轮落盘的旧值盖掉；
   - `_run_det_batch_inference.on_progress` 当场写 `_infer_times`，不用等异步回填。

## 3. 兼容性 / 你能看到的变化

- **老 `outputs/*.det.json` 没有 `meta`**：重启后「分数」会自动补上（scores 本来就存在），
  **「耗时」仍然是空** —— 那些时间从来没被记录过，只能重跑一次批量推理才有。
- 拿现有数据对一下数（重启后列表应显示）：
  ```
  字符-20261112 (1)   14 框  平均置信度 0.9183 → 91.8%
  字符-20261112 (82)  10 框  平均置信度 0.9535 → 95.3%
  ```
- 打开工程时（`_open_project` → 后台线程）就会加载，不需要先进一次推理。

## 6. 顺手发现（**没改，需你定**）

`_run_det_inference_single()`（单图检测推理）是这样的：

```python
boxes = dt.predict(...)
if boxes:
    self._box_manager.delete_all()          # 清掉当前图的**标注**
    for b in boxes:
        self._box_manager.add_box(...)      # add_box 里直接 self.save()
```

而 `BoxManager.save()` 写的是 `images/<base>_det.json` —— **标注文件**。
也就是说：**在一张已标注的图上点单图推理，你的标注会被预测结果整体替换**。
和批量的口径（预测写 `outputs/`、标注留 `images/`）不一致。

`delete_all()` 前有 `_snapshot()`（可 Ctrl+Z），也有版本快照，但用户不会预期"点个推理把标注冲了"。
建议改成：预测走画布的预测层（`_det_overlay` + `load_predictions`），或者至少"有标注时先问一句"。
