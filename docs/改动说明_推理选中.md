# 右键「推理选中的图像」

日期：2026-11-16　提交：见 `git log`

用户提需求（附友商截图）：图片列表右键能对**选中的图片**跑一遍推理。

## 做法

不是逐张调单图推理 —— 单图那条路是**同步**的，选 50 张就卡界面 50 次，
还没有进度、没法取消。改成**复用批量流水线，只把图片清单换掉**：

```
右键选中 → _infer_selected_images(rows)   # 行 → 路径、去重、跳过不存在的
        → _enqueue_inference(paths)       # 进任务队列（可取消、串行不抢显存）
        → _dispatch_batch_inference(..., only=paths)
        → _run_det_batch_inference / _run_seg_batch_inference(..., only=paths)
        → BatchRunner.run(images=paths)   # 和"全部"同一条流水线
```

好处全跟着来：进度条、任务队列里那一行（`推理选中·检测 [205412]（3 张）`）、
× 取消、结果写 `outputs/`、`meta.infer_ms` 落盘、列表「结果/分数/耗时」回填 ——
和"批量推理全部"完全一致。

## 范围（刻意保守）

| 工程类型 | 行为 |
|---|---|
| 目标检测 | ✅ 只跑选中 |
| 单视图分割 | ✅ 只跑选中 |
| 分类 / OCR | 提示"暂不支持只跑选中，请用「开始推理」"（它们的批处理按目录遍历，传子集会被**忽略**——宁可说不支持，也别假装跑了） |
| 多视图分割 | 提示同上（按"组"喂 9 通道，单张挑出来会崩） |

没选图 / 选中的文件都不存在 → 提示一句，不发起空任务。
选中里混了已删除的图 → 跳过并在日志里说跳过了几张。

## 测试（`tests/test_infer_selected.py`，7 条）

| 用例 | 守什么 |
|---|---|
| ★ 只把选中的行送进流水线 | 选中 {0,2} → 恰好那两张 |
| 没选中任何图片 | 提示，不发任务 |
| 选中里混了已删除的图 | 跳过，其余照跑 |
| 选中的全不存在 | 只提示 |
| ★ 清单真的到了 `BatchRunner.run` | 不只测入口，测到流水线那一层 |
| ★ 分派层透传 `only` | 补变异漏掉的那一层 |
| 分类工程 | 明确说不支持 |

变异 **4/4**：跑成全部图片、分派时不透传、不过滤已删除文件、分类工程也放行。

**第一版漏了第 2 条**：用例直接调 `_run_det_batch_inference`，绕过了分派层，
"分派时把 only 丢掉"照样全绿。补了"分派层透传 only"用例后 4/4。

## 影响面

- `_batch_inference()` 的签名和按钮接线**没变**（`clicked.connect(self._batch_inference)`），
  只把原来的函数体挪进 `_enqueue_inference(only=None)`。新增参数走关键字，
  不会被 Qt 的 `checked=False` 顶掉。
- `_run_seg_batch_inference` / `_run_det_batch_inference` 多了 `only=None`，
  不传就是老行为（`list_images` 全部）。
